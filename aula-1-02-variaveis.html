Por que o programa precisa guardar coisas

Na lição anterior, o total da padaria dependia de valores calculados antes: o total dos pães precisava existir quando o café fosse somado. O programa precisa guardar um valor agora para usar depois. É para isso que servem as variáveis.

Uma variável é um nome que aponta para um valor guardado na memória. Você cria o nome uma vez e usa quantas vezes quiser:

Lendo em voz alta: "crie a variável pontos e coloque nela o valor 10; depois, mostre o valor de pontos".

💡 Analogia: Uma etiqueta colada num valor

Pense na variável como uma etiqueta com um nome, colada num valor. let pontos = 10 cola a etiqueta "pontos" no número 10. Quando você escreve pontos no código, o computador segue a etiqueta até o valor.

Trocar o valor (pontos = 15) é descolar a etiqueta do 10 e colar no 15. O 10 não "vira" 15: a etiqueta passa a apontar para outro valor.

Onde a analogia para de funcionar

Muita gente aprende que variável é uma "caixa que guarda um valor". Para números e textos, as duas imagens funcionam igual. A diferença aparece com listas e objetos: const b = a cola uma segunda etiqueta na mesma lista, não faz uma cópia. Mudar a lista por b muda o que você vê por a. Com a imagem da caixa, você esperaria duas listas separadas. Isso aparece de verdade na lição de listas e objetos (lição 7): guarde a imagem da etiqueta.

let e const

JavaScript tem duas palavras para criar variáveis no código moderno:

Palavra Pode receber outro valor depois? Quando usar
const Não Quando o valor não muda: um preço fixo, um nome, um resultado já calculado
let Sim Quando o valor muda: um placar, um contador, um saldo

A regra prática é: comece com const; troque para let só quando precisar mudar o valor. Assim, quem lê o código sabe na hora o que pode mudar.

A segunda linha, placar = placar + 3, confunde muita gente. O = em programação não é igualdade: é atribuição. Leia assim: "calcule placar + 3 com o valor atual (0 + 3) e cole a etiqueta placar no resultado (3)". Primeiro o lado direito, depois o esquerdo.

Erro comum: usar a variável antes de criar

Dá erro (Cannot access 'total' before initialization). O computador lê de cima para baixo: na linha 1, a variável ainda não foi criada. É por isso que o visualizador mostra "(ainda não criada)" antes da linha do let ou do const.

Erro comum: criar a mesma variável duas vezes

let x = 1; e depois let x = 2; dá erro: o nome x já existe. Para trocar o valor, escreva só x = 2;, sem o let.

Tipos de valor

Todo valor tem um tipo. Os três que você mais vai usar agora:

Tipo Exemplos Para quê
number (número) 7, 1.5, -3 contas
string (texto) "Ana", 'pão', `olá` palavras e frases, sempre entre aspas ou crases
boolean (lógico) true, false respostas de sim ou não

O comando typeof diz o tipo de um valor: typeof 7 é "number"; typeof "7" é "string". Essa diferença importa: 7 + 1 dá 8, mas "7" + 1 dá "71", porque + com texto junta em vez de somar.

Exemplo resolvido: Trocar o valor de duas variáveis

Problema: a vale 1 e b vale 2. Queremos que a passe a valer 2 e b passe a valer 1.

Tentativa ingênua: a = b; e depois b = a;. Não funciona: depois da primeira linha, a já vale 2, e o valor 1 se perdeu. As duas terminam valendo 2.

Solução: guardar o valor antigo numa terceira variável antes de sobrescrever.

  1. Guardar o valor de a em temporaria (temporaria = 1).
  2. Colar a no valor de b (a = 2).
  3. Colar b no valor guardado (b = 1).

Nível 2 Por dentro: O que acontece na memória

Quando o motor JavaScript roda let pontos = 10, ele reserva um espaço na memória para o número 10 e anota, numa tabela chamada ambiente léxico (o "caderno de nomes" daquele trecho do código), que o nome pontos aponta para esse valor.

Com let e const, o nome é registrado no caderno assim que o bloco começa, mas fica marcado como "não pode usar" até a linha da criação rodar. Esse intervalo tem nome: zona morta temporal (temporal dead zone). É exatamente o que o visualizador mostra como "(ainda não criada)", e é por isso que usar antes dá erro, em vez de dar undefined.

Existe uma terceira forma antiga, var, que não tem essa proteção e tem outras regras de alcance. Você vai encontrar var em códigos antigos; em código novo, use let e const.

Nível 3 Na documentação oficial: Onde isso está na documentação

Na MDN, leia as páginas de let, const e typeof. Procure nelas as expressões temporal dead zone e block scope (alcance de bloco): são os dois conceitos que você acabou de ver com outros nomes. A página da especificação oficial (ECMAScript) é bem mais difícil: por enquanto, basta saber que ela existe e que a MDN é a porta de entrada.

Resumo

  • Variável é um nome (uma etiqueta) que aponta para um valor.
  • const para o que não muda; let para o que muda. Na dúvida, comece com const.
  • O = é atribuição: calcula o lado direito e cola a etiqueta do lado esquerdo no resultado.
  • Não dá para usar a variável antes da linha que a cria, nem criar o mesmo nome duas vezes.
  • Tipos principais: number, string e boolean. Com texto, o + junta: "7" + 1 dá "71".
